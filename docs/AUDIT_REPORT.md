# App Audit Report — 2026-05-09

Generated by three parallel subagents (end-user-tester, ux-auditor, visual-qa-auditor) against localhost:3001 with a fresh local Podman PostgreSQL instance.

**Status key:** `[ ]` = not fixed · `[x]` = fixed

## Critical — Fix before M8 (going public)

- [ ] **C1 — `error.tsx` and `not-found.tsx` missing**
  - Next.js falls back to its generic white-background default pages. Any 404 or runtime error sends a visitor to an unstyled page with no nav and no way home.
  - Fix: create `src/app/error.tsx` and `src/app/not-found.tsx` matching the Engineering Logbook aesthetic (CSS vars, Newsreader font, back-to-home link). `error.tsx` must accept and call the `reset` prop.

- [ ] **C2 — Projects have no publish mechanism (P1 bug)**
  - `publishedAt` is absent from `ProjectForm` state and the PUT route's update object silently ignores it. All created projects are permanently draft — they never appear on the public `/projects` page.
  - Fix: add `status` / `publishedAt` toggle to `src/components/admin/ProjectForm.tsx` (mirror the pattern from `PostForm.tsx`) and add `publishedAt` to the update data in `src/app/api/admin/projects/[id]/route.ts`.

- [ ] **C3 — `deletePost` fires instantly, no confirmation, missing `revalidatePath`**
  - One misclick destroys a published post permanently. The Server Action also omits `revalidatePath("/admin/blog")` so the deleted row stays visible until a manual refresh.
  - Fix: add a confirmation step (client-side `confirm()` or modal) before the Server Action fires; add `revalidatePath("/admin/blog")` inside `deletePost` in `src/app/admin/(panel)/blog/page.tsx`.
  - Note: `deleteProject`, `deleteSkill`, `deleteExperience` all call `revalidatePath` correctly — this one was missed.

- [ ] **C4 — Delete on projects, skills, and experience has no confirmation**
  - Same one-click-destroy pattern. All unrecoverable on a sole-admin system.
  - Fix: add confirmation step to delete buttons in `src/app/admin/(panel)/projects/page.tsx`, `skills/page.tsx`, `experience/page.tsx`.

## P2 Bugs — Broken API behaviour

- [ ] **B1 — `POST /api/admin/skills` returns 500 on invalid enum value**
  - Invalid `category` values cause an unhandled `PrismaClientValidationError` to propagate as 500.
  - Fix: wrap the Prisma call in try/catch; catch `PrismaClientValidationError` and return 400 with a message listing valid `SkillCategory` enum values.
  - File: `src/app/api/admin/skills/route.ts`

- [ ] **B2 — `POST /api/admin/posts` returns 500 on duplicate slug**
  - Unhandled Prisma `UniqueConstraintViolation` (code `P2002`). Occurs in normal admin workflow.
  - Fix: catch `error.code === 'P2002'` and return 409 with `"a post with this slug already exists"`.
  - File: `src/app/api/admin/posts/route.ts`

- [ ] **B3 — `POST /api/admin/career/evaluate` returns 500 when career-ops is unreachable**
  - `fetch()` throws `ENOTFOUND career-ops` (unhandled) → 500 after 3.8s timeout.
  - Fix: wrap the fetch in try/catch and return `{ status: 503, error: "career-ops service unavailable" }`.
  - File: `src/app/api/admin/career/evaluate/route.ts`

## UX Issues — Broken or confusing flows

- [ ] **U1 — Agent report Server Actions silently swallow all errors**
  - All five Server Actions (`applySkillAdd`, `applyAllSkillAdditions`, `applySkillUpgrade`, `applyProjectSyncUpdate`, `createSeriesDrafts`) have empty `catch {}` blocks. DB write failures show no feedback — the UI appears unchanged and users don't know to retry.
  - Fix: surface errors via state (error banner, toast, or re-throw) in each catch block.
  - File: `src/app/admin/(panel)/agents/reports/[reportId]/page.tsx`

- [ ] **U2 — No unsaved-changes guard in PostForm / ProjectForm**
  - Clicking Cancel or browser Back discards everything silently — including AI-generated content that may have taken 30 seconds to produce.
  - Fix: add a `beforeunload` listener or a dirty-check (`form !== initialForm`) that shows a confirmation prompt on Cancel/Back.
  - Files: `src/components/admin/PostForm.tsx`, `src/components/admin/ProjectForm.tsx`

- [ ] **U3 — PostForm save button label doesn't reflect publish intent**
  - Button always reads "Create post" / "Update post" even when the status dropdown is set to PUBLISHED. Accidental publishing is a real risk.
  - Fix: change button label to "Publish" (or "Save & publish") when `form.status === "PUBLISHED"`.
  - File: `src/components/admin/PostForm.tsx`

- [ ] **U4 — RunAgentButton 409 "already running" is tooltip-only**
  - The button turns red and reads "Failed" — the reason "already running" is only in a `title` tooltip, invisible on touch devices.
  - Fix: render the error message as inline text below the button, not only as a `title` attribute.
  - File: `src/components/admin/RunAgentButton.tsx`

- [ ] **U5 — Mobile nav: no outside-click close, no focus trap**
  - Tapping outside the open drawer doesn't close it. Keyboard users tab into main content behind the drawer (WCAG 2.1.2 issue).
  - Fix: add an overlay `div` that captures outside clicks; add `focus-trap` logic while the drawer is open.
  - File: `src/components/public/Nav.tsx`

- [ ] **U6 — Contact form: 429 rate-limit shows same generic error as 500**
  - Users who hit the rate limit (5/hour) see "Something went wrong, email me directly" with no indication of when they can retry.
  - Fix: check `res.status === 429` separately and show "Too many messages — please wait an hour and try again".
  - File: `src/components/public/ContactSection.tsx`

- [ ] **U7 — Stale skills section in agent report detail is a dead end**
  - "Possibly Stale" skills are listed with no Dismiss / Remove action. Users must navigate away and find them manually.
  - Fix: add a "Remove skill" button or "Dismiss" action next to each stale skill entry.
  - File: `src/app/admin/(panel)/agents/reports/[reportId]/page.tsx`

## P3 — Minor functional issues

- [ ] **M1 — Projects filter missing "Research" option** *(one-liner)*
  - `FILTERS` array = `["All", "Software", "Robotics", "Hardware"]` — RESEARCH omitted despite existing in the schema.
  - Fix: add `"Research"` to the `FILTERS` array.
  - File: `src/components/public/ProjectFilter.tsx`

- [ ] **M2 — ExperienceSection renders an empty header when DB has no entries**
  - Section heading and nav anchor render, content area is blank. Skills and BlogPreview correctly return `null` when empty.
  - Fix: add `if (experience.length === 0) return null;` (or a styled empty state) at the top of the component.
  - File: `src/components/public/ExperienceSection.tsx`

- [ ] **M3 — Skills admin page: empty categories render blank (no message)**
  - When no skills exist, all 7 categories return `null` with no "No skills yet" message.
  - Fix: add an empty-state card when `grouped` has no entries (match the pattern in blog/projects pages).
  - File: `src/app/admin/(panel)/skills/page.tsx`

- [ ] **M4 — Theme toggle flashes on hydration**
  - `Nav.tsx` initialises `theme` state as `"light"` and reads `localStorage` in `useEffect`. A brief flip can occur on slow connections.
  - Fix: initialise state from `document.documentElement.getAttribute("data-theme")` synchronously (the `beforeInteractive` script already sets it), or initialise as `null` and render nothing until hydrated.
  - File: `src/components/public/Nav.tsx`

- [ ] **M5 — `?error=slug-exists` query param persists in URL**
  - After a slug-conflict redirect, the error param stays permanently in the URL.
  - Fix: call `router.replace(pathname)` after reading and displaying the error from `searchParams`.
  - File: `src/app/admin/(panel)/agents/reports/[reportId]/page.tsx`

- [ ] **M6 — Cover image field has no format validation or preview**
  - Any free-text URL is accepted; broken URLs only surface on the public page.
  - Fix: add a URL format check and an inline `<img>` preview that shows on valid URL input.
  - Files: `src/components/admin/PostForm.tsx`, `src/components/admin/ProjectForm.tsx`

## Design System Violations

- [ ] **DS1 — `ProjectFilterTabs.tsx` is dead code with admin-panel styling in the public directory** *(Critical)*
  - Uses `slate-*`, `#2a2d3a`, and per-type Tailwind semantic colours in `src/components/public/`. Zero import references — never rendered.
  - Fix: delete the file, or rebuild it from scratch using logbook CSS vars before using it.
  - File: `src/components/public/ProjectFilterTabs.tsx`

- [ ] **DS2 — `MockModeBanner.tsx` uses Tailwind color utilities instead of CSS vars** *(Critical)*
  - `text-amber-300`, `bg-amber-400`, `animate-pulse` in a public component violate the design token contract.
  - Fix: refactor to use `var(--accent)` and `var(--ink-soft)`, or move to `src/components/dev/MockModeBanner.tsx`.
  - File: `src/components/public/MockModeBanner.tsx`

- [ ] **DS3 — `.btn-link` font inconsistency**
  - `globals.css` assigns `font-inter-tight` to `.btn-link`. `ContactSection.tsx:184` overrides inline to Newsreader italic; `BlogPreviewSection.tsx:95` uses `--font-mono`. Two diverging overrides.
  - Fix: decide the canonical `.btn-link` font (Newsreader italic is most logbook-appropriate), update `globals.css`, remove inline overrides.
  - Files: `src/components/public/ContactSection.tsx:184`, `src/components/public/BlogPreviewSection.tsx:95`, `src/app/globals.css`

- [ ] **DS4 — ExperienceSection uses `!important` on mobile color override**
  - `.exp-row .mono { color: var(--accent) !important; }` inside an inline `<style>` block — fragile.
  - Fix: give the date spans a specific class instead of overriding `.mono` globally within `.exp-row`.
  - File: `src/components/public/ExperienceSection.tsx:89`

- [ ] **DS5 — Admin save confirmation uses `bg-emerald-500` (outside admin palette)**
  - Approved admin accent is `cyan-500`. The emerald green "saved" flash is outside the defined palette.
  - Fix: replace with `bg-cyan-600` or a `border-cyan-500` outline state.
  - Files: `src/components/admin/PostForm.tsx:459`, `src/components/admin/ProjectForm.tsx:271`

- [ ] **DS6 — RunAgentButton uses red/green outside admin palette**
  - `text-red-400`, `text-green-400` for error/success states — not in the `#0f1117 / slate / cyan` system.
  - Fix: use `text-slate-400` + a cyan indicator for success, `text-slate-300` + border highlight for error.
  - File: `src/components/admin/RunAgentButton.tsx:64–66`
